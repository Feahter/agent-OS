# Agent OS 0.1 执行计划

## 阶段目标

让用户不需要理解 GraphSpec 或各家 Agent 参数，也能提交目标、看懂进度并获得经过验证的结果。实现顺序以用户体验风险为准：先建立基线，再改变入口，最后让系统学习优化。

## 工作包

### P1：真实项目评测基线
[deps: 0.0.1] [status: in_progress]

- P1.1：定义不保存 prompt、项目路径和原始响应的评测场景与运行记录。
- P1.2：从工程工作流报告提取成功、验证、耗时、费用、人工介入和恢复指标。
- P1.3：生成不可覆盖的基线快照，支持后续版本比较。
- P1.4：选择三个低风险真实项目，小流量运行 Codex、Claude Code、Pi 和 Orca。

验收：离线 fixture 可重复生成同一摘要；损坏或不完整数据失败关闭；真实运行必须由用户明确允许模型费用和目标项目。

### P2：统一任务接口
[deps: P1.2] [status: completed]

- 提供 `do / status / approve / control / result` 五个稳定动作。
- GraphSpec 保留为高级接口，普通任务不要求用户编写 JSON。
- 输出面向人的摘要，同时保留机器可读模式。

验收：常见单仓库任务在项目一次性初始化后只需要目标和一次关键审批；五个动作共享同一任务状态，不建立第二套真相来源。

### P3：意图编译与任务模板
[deps: P2] [status: completed]

- 将目标和约束编译为可审阅的执行计划。
- 首批覆盖修复、测试、重构、调研和发布准备。
- 缺少关键上下文时提问，其余使用安全默认值。

验收：计划可解释、可验证、摘要变化会使审批失效；模板不绕过项目规则、预算和 Reality Anchor。

### P4：本地常驻协调器
[deps: P2, P3] [status: pending]

- 后台运行任务，支持排队、优先级、暂停、继续和取消。
- 将现有控制面、审批收件箱、检查点和 Orca 协调器接入单一驻留进程。
- 终端退出后任务继续，重启后从持久状态恢复。

验收：没有第二套调度、重试或审批所有权；崩溃不会重复外部副作用。

### P5：真实兼容矩阵与故障注入
[deps: P1.2] [status: pending]

- 对真实 Codex、Claude Code、Pi 和 Orca 做版本化协议验收。
- 覆盖超时、限流、协议漂移、进程崩溃、工作区漂移和恢复。
- 默认离线运行；真实模型调用独立开关并记录费用。

验收：每个支持版本都有协议证据和最近验证时间；未知协议失败关闭。

### P6：个人化 RSI 与成本优化
[deps: P1.3, P3, P5] [status: pending]

- 根据任务类型联合优化质量、费用、耗时和人工介入。
- 增加可查看、可纠正、可遗忘、可导出的个人与项目记忆。
- 所有策略候选继续经过回归、审批、灰度和回滚。

验收：固定评测集质量不下降；重复任务成本或耗时有可测量改进；用户能解释并撤销每项学习结果。

## 当前迭代

本轮已完成 P1.1–P1.3、P2 与 P3 的最小闭环。P1.4 会产生真实模型费用并操作外部项目，单独取得授权后执行；下一优先级为 P4 本地常驻协调器。
